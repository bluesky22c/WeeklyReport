ELP, EQ AI Agent 개발

​※ 개요

  설비 담당자가 한국말로 물으면 프로그램이 알아서 로그·알람·레시피·설비상태를 찾아 답하는 사내 전용 AI. 외부 서비스 없이 현장 PC단독 구동이 전제라, 공개 기본 모델(4B급)을 그대로 쓰는 대신 설비 용어와 조회 규칙을 직접 가르치는(파인튜닝) 방식. 3개 축으로 진행 — 모델 학습(Tuning) / 성능 시험대(Harness) / 설비 연동(Runtime).


1. Tuning Part (모델 파인튜닝)


  ● 파인튜닝 전(기본 모델) vs 후 - 동일 문제집 263문항 / 측정 9회

    조회 기능 선택 정확도 85.2% => 96.2% | +11.0%

    조회 조건 정확 추출 67.7% => 95.5% | +27.8%

    정해진 형식 준수 92.0% => 100% | 응답 실패0건

    질문당 응답 시간 | 약 1.2초 | 현장 PC 단독 구동 

    ○ 기본 모델은 설비 호칭·기간 표현을 못 알아들어 조회 조건 3건 중 1건이 틀리는 수준 → 파인튜닝 후 20건 중 19건 정확 수준

    ○ 기본 모델에서 20건 발생하던 응답 실패(형식 이탈·무한 반복)는 완전 소멸


  ● 향상 근거 분리 - "기능 설명문 개선 기여"와 "학습 기여"를 나눠 측정. 효과 없는 개선안 1건은 실측 후 폐기(감이 아니라 수치로 채택·폐기 결정)

  ● 조건 지어내기 9건 → 0건

  ● 제어 명령("검사 시작") 학습·평가 축 신설, 신규 명령 24/24 정확 인식 확인. 제어 편입 후 첫 파인튜닝 런 착수(학습 606건 / 평가 355건)


2. Harness Part (성능 시험대)

  ● 파인튜닝 전 기본 모델을 기준선으로 먼저 측정 → 이후 학습본을 동일 조건, 9회 연속 채점. 향상폭을 항목별로 비교 가능하게 함

  ● 오답 원문 전량 보관해 유형 분해 - 설비 호칭 22건·기간 표현 13건이 전체 오답의 73%임을 확인, 개선 우선순위 근거로 사용

  ● 결함 3건 발견·수정 - 무한 반복·공백 폭주로 응답이 멈추던 원인 2건(기본 모델 응답 실패 20건의 원인), 채점 사각지대 1건(실제 10건 누락)

  ● 기능 목록·설명문이 3곳에 흩어져 서로 달라지던 것을 한 곳에서 배포하도록 정리(현재 12종) - 폐기 문구가 학습 데이터에 섞이던 사고 재발 방지


3. Runtime Part (설비 연동 · RAS 내장)

  ● 조회 실데이터 연결 — 로그·알람·레시피·현재시각·택트타임·설비상태·PG상태

    ○ 알람 원본이 DB 가 아니라 운전 로그의 오류 줄임을 실데이터 대조로 확인

    ○ 현장 제어PC 로그 26일분으로 실제 파일 위치·택트 원본 확정

  ● 에이전트 서버를 RAS 프로그램 안에서 구동하도록 통합(별도 프로세스 → 내장)

  ● 제어 요청은 설비 상태(운전 중·인터락) 확인 게이트 통과 필수.

  ● 실제 명령 전달 배선은 안전 확인 후 연결 예정(현재 미연결)

  ● 가상 제어PC 에 현장 다용 명령 4종 보강 — 설비 없이 검증 가능

  ● 현장 질문 이력 기록 신설 → 실사용 응답 실패 14건 원인 3종 규명·수정,

    갈라져 있던 질문 처리 경로 3곳을 하나로 통합

  ● 제어 관련 항목 추가 구성 및 검증중
